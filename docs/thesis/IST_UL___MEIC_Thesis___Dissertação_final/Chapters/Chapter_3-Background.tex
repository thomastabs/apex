\fancychapter{Research Background}
\label{chap:background}

This chapter presents the theoretical background relevant to the research: Artificial Intelligence, the Software Development Life Cycle, AI in Software Development, Vibe Coding, and Spec-Driven Development.

\section{Artificial Intelligence}

Artificial Intelligence refers here to systems performing tasks associated with human cognition, while Generative AI denotes systems that produce new content such as text, images, audio or code. Large Language Models (LLMs) are a class of Generative AI trained on large text and source-code corpora, typically using transformer architectures.

In software engineering, LLMs can interpret natural-language intent and generate, explain, refactor, document and test code across multiple programming languages. These capabilities make them useful as collaborative tools throughout software development, supporting both novice and experienced developers while reducing manual effort in repetitive or knowledge-intensive tasks \cite{Ahmed:2025ai,AlHashimi:2025er,Banh:2025cf,Basha:2025tt,Chen:2025es,Durrani:2024ad,Haque:2025la,Hou:2025cl,Jabrw:2025ss,Kim:2025ao,Moore:2025vc,Terragni:2025fa,Wang:2025rs,Zhang:2025ea}.

\section{Software Development Life Cycle}

The Software Development Life Cycle (SDLC) structures software development into requirements, design, implementation, testing, deployment and maintenance phases~\cite{Ahmed:2025ai}. It is central to this research because AI participates differently across these stages. Although Agile and DevOps have increased iteration and automation, many activities remain manual and time-consuming, including debugging, documentation, repository consistency and routine implementation. As systems become more complex, pressure to improve productivity without compromising maintainability or security has driven interest in AI-assisted workflows \cite{Zhang:2025ea,Ahmed:2025ai,Jabrw:2025ss,Terragni:2025fa}.

\section{AI in Software Development}

LLMs are increasingly used to accelerate prototyping, explain unfamiliar code, support documentation and assist with implementation. Their role is generally collaborative rather than fully autonomous: the model generates, summarises or proposes, while developers remain responsible for architectural decisions, validation, integration and alignment with requirements.

Research therefore increasingly focuses on how workflows adapt to this division of labour, how trust in AI-generated output is formed, and how responsibility is distributed between human judgement and automated generation. These issues are examined in detail in \Cref{chap:slr} \cite{Ahmed:2025ai,Zhang:2025ea,Durrani:2024ad,Jabrw:2025ss,Banh:2025cf,Farhanna:2025eu,KarlovsKarlovskis:2024ga,Terragni:2025fa}.

\section{Vibe Coding}

Vibe Coding describes a development style in which developers express intent, requirements or constraints in natural language and a generative model produces corresponding code or related artefacts. Development proceeds conversationally, with the developer evaluating and refining generated output rather than beginning from manually written code. This shifts part of the programming effort from direct implementation towards specification and review, affecting developer workflow, cognitive effort and responsibility across the SDLC \cite{Moore:2025vc,Zamfiroiu:2025ec}.

\section{Spec-Driven Development}
\label{sec:background_sdd}

Spec-driven development is an emerging practice in which a persistent, versioned specification becomes the primary reference for both developers and AI agents. Rather than generating code directly from loosely defined prompts, the model works against explicit requirements, design decisions and constraints that are maintained alongside the codebase. Industry examples include AWS Kiro, GitHub Spec-Kit and the Tessl Framework, all of which place stronger emphasis on persistent specification artefacts \cite{Thoughtworks:2025SD}. Thoughtworks identifies the approach as an emerging AI-assisted engineering practice, while Farrag describes it as a form of specification-driven governance, although that work remains a preprint \cite{Thoughtworks:2025SD,Farrag:2026sd}.

The relevance to this dissertation is that an explicit specification gives AI-generated output a stable reference against which it can be constrained and validated. This principle directly motivates the Spec-Anchored Continuity mechanism introduced in \Cref{chap:proposal}.
